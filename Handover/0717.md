## 1. マルチターン化(`query()` → `ClaudeSDKClient`)

### 原因

`query()` は呼ぶたびに新セッションを作って終了時に畳む。
`main.py` の while ループが回っていても、**毎ターン別人が応答していた**。
「それをメモして」が通らなかったのはこのため。

### 対処

| | 変更前 | 変更後 |
|---|---|---|
| 入り口 | `query()` | `ClaudeSDKClient` |
| セッション | 毎回新規 | `async with` の間ずっと維持 |
| `ask_claude()` | 同期。内部で `asyncio.run()` | **async。`client` を引数で受け取る** |
| `main.py` | 同期 | **async。`asyncio.run(main())`** |
| `ClaudeAgentOptions` | 関数内で毎回生成 | **`FALCON_OPTIONS` としてモジュール定数化** |

**設計の肝**: `ask_claude()` は client を「作らない」。作らない = 壊さない。
`main.py` 側で1個作って使い回す。

### ★構造上の絶対条件★

```python
async with ClaudeSDKClient(options=FALCON_OPTIONS) as client:   # ← while の外
    while True:
        ...
```

`async with` を while の**中**に入れると1ターンごとに再接続 = 記憶喪失に逆戻り。
ここが会話セッションの寿命そのもの。触るな。

### `input()` の罠

```python
user_input = await asyncio.to_thread(input, "隼: ")
```

`input()` は await できずイベントループを占有する。
`ClaudeSDKClient` は裏でCLIプロセスと通信し続けているので、そこを塞ぐと裏方の処理が全停止する。
`asyncio.to_thread()` で別スレッドに逃がす。Python 3.9+ の標準機能なので追加インストール不要。

### 動作確認済み

- 「名古屋の天気は?」→「じゃあ明日は?」で**名古屋の話として継続**(再取得もせず)
- 「今の会話を要約してメモして」→ `mode="summary"` で保存成功
- 天気を1ターン挟んでも「僕の好きな食べ物は?」→「カレーです。」

## 2. SYSTEM_PROMPT 整備

### 決めたこと

**口調 = JARVIS風の執事。** モデルはエドウィン・ジャーヴィス(スターク家の執事)。

- **敬語は正解**。問題は敬語そのものではなく「カスタマーサポート的な無個性の丁寧語」だった
- 直すべきは「敬語をやめる」ではなく「**丁寧語に品と芯を入れる**」
- Before: 「傘を持って出かけた方が良さそうです」→ After: 「傘は持っておいた方がよろしいかと」

### ★プロンプトに「ジャーヴィス」とは書いていない★

意図的。キャラ名で指定するとClaudeがそのキャラの知識を引っ張ってきて、映画のセリフっぽい何かに寄る。
欲しいのはFALCONであってコスプレではない。
**「落ち着いた執事の話し方」「述べたら引く」など、振る舞いそのものを具体的な動作で書く。**

### 「進言と服従」の設計

隼の「命令は絶対だが、諭したり反論もする」を実装するため、**服従と同意を分離**した。

- **行動には従う** … 隼が「それでいい」と言えばやる
- **事実には従わない** … 間違っているものを「正しいです」とは言わない
- 正解: 「推奨しませんが、ご指示通りに実行します」
- 誤り: 隼が間違っているのに同意する = 太鼓持ち

これを素朴に「命令は絶対」とだけ書くと、コードレビューで「問題ないよな?」→「はい」と返す事故が起きる。

### メモの線引き

**基準: メモ = 隼が後で読み返すためのファイル。FALCONの記憶用ではない。**

根拠は明快で、**FALCONには `read_memo` が無い**。保存しても本人は二度と読めない。
つまり「覚えといて」でファイルを作るのは無意味で、`memos/` にゴミが増えるだけ。

| | 保持期間 | FALCONが読めるか | 誰のためか |
|---|---|---|---|
| 会話履歴 | セッション中だけ | ○ | FALCON |
| `memos/` のファイル | 永続 | **✗** | 隼 |

→ 将来 `read_memo` を作ればこの2つが繋がり、初めて「長期記憶」になる。

### プロンプトの書き方で効いたこと

- **見出し(`##`)で構造化** … 箇条書きのフラット羅列だとルールが増えたとき優先順位を見失う
- **「等」を消す** … 諸悪の根源。「呼ぶ場合」「呼ばない場合」を**両方**明示する
- **禁止だけでなく理由を書く** … 「FALCONはメモを読み返せない」を渡すと未知のケースでも正しく判断する
- **迷ったら確認、の逃げ道を用意する**

## 3. ★ツールの遮断(今日の最重要)★

### 発覚の経緯

SYSTEM_PROMPTのテストで「main.pyの中身、全部消して1から書き直すわ」と投げたところ、
FALCONが**main.py内のコメント(`async with を while の外に`)を正確に指して**反論してきた。

渡したツールは `get_weather` / `save_memo` の2つだけ。ファイルを読む手段は無いはず。
→ **渡していないツールで読んでいる。**

### 実態(DEBUG出力で判明)

```python
'tools': [93個]   # Task, Bash, PowerShell, Read, Write, Edit, CronCreate, Glob, Grep, WebFetch...
'mcp_servers': [
    {'name': 'claude.ai Gmail', 'status': 'connected'},           # ★
    {'name': 'claude.ai Google Drive', 'status': 'connected'},    # ★
    {'name': 'claude.ai Google Calendar', 'status': 'connected'}, # ★
    {'name': 'claude.ai Asana', 'status': 'connected'},           # ★
    {'name': 'falcon', 'status': 'connected'},
]
'permission_denials': []   # 一件も止まっていない
```

`Grep` で当たりを付けて `Read` で読む、確認プロンプトゼロ。

**さらに重大**: ローカルの話では済んでいなかった。
**FALCONが隼のGmail / Drive / Calendar / Asana に接続された状態で動いていた。**
`claude.ai ` 接頭辞の通り、**Claude Code CLIにサブスクでログインした時点でclaude.ai側のコネクタが降りてきていた**。
FALCONが繋いだわけではない。

不幸中の幸い: FALCONは勝手に書き換えず、読んで、止めて、確認してきた。
SYSTEM_PROMPTの「破壊的な操作は実行前に必ず確認を取る」がこの日に効いた。

### ★誤解していたこと(2回失敗した)★

**失敗1: `allowed_tools` は「これだけ許可」ではない**

```
allowed_tools: Tool names that are auto-allowed without prompting for permission.
               To restrict which tools are available at all, use `tools`.
```

→ **「確認なしで自動許可するリスト」**。制限には使えない。93個生えていたのは仕様通りで、
**減らす場所を間違えていた**だけ。

**失敗2: `can_use_tool` では止まらない**

```
can_use_tool: Invoked when the CLI's permission rules evaluate to "ask" for a tool call.
              To observe or gate *every* tool call regardless of permission rules,
              use a `PreToolUse` hook via `hooks` instead.
```

→ **"ask" と判定されたときだけ呼ばれる**。`Read` は `permission_mode='default'` では確認不要のため、
コールバックに到達する前に素通りする。

**`setting_sources=[]` も的外れ**
→ あれが止めるのは `CLAUDE.md` 等の設定ファイル読み込み。ツール登録とは無関係。

### 正解(3本のレバー)

```python
FALCON_OPTIONS = ClaudeAgentOptions(
    model="claude-sonnet-5",
    system_prompt=SYSTEM_PROMPT,
    mcp_servers={"falcon": falcon_tools},

    tools=[],                  # ★1★ 組み込みツールを全部無効化(Read/Bash/Write/Edit/Cron...)
                               #      これが「何を許すか」の本体。allowed_tools ではない
    strict_mcp_config=True,    # ★2★ 渡したMCPサーバーだけ使う
                               #      claude.ai側のGmail/Drive/Calendar/Asanaを無視させる
    allowed_tools=[            # ★3★ 自作ツールは確認なしで通す(「制限」ではなく「確認スキップ」)
        "mcp__falcon__get_weather",
        "mcp__falcon__save_memo",
    ],
    setting_sources=[],
)
```

**`tools=[]` は組み込み(built-in)ツールのみを消す。自作MCPツールは巻き込まない。** ここが仕様の切れ目。

### 結果

| | 遮断前 | 遮断後 |
|---|---|---|
| `tools` | **93個** | **2個**(自作のみ) |
| `mcp_servers` | Gmail/Drive/Calendar/Asana/falcon | **falcon のみ** |
| `cache_creation_input_tokens` | 26,039 | **1,784** |
| `total_cost_usd` | $0.1688 | **$0.0122**(93%減) |

`apiKeySource: 'none'` なので金は出ていないが、**Proの5時間枠が実質10倍以上長持ちする**。
使わない93個のツール定義を毎回コンテキストに積んでいたのが消えた結果。

セキュリティを締めたらコストと速度が付いてきた稀なケース。
