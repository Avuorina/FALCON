## 1. マルチターン化(query() → ClaudeSDKClient)

### 原因
query() は呼ぶたびに新セッションを作って終了時に畳む。
main.py の while ループが回っていても、**毎ターン別人が応答していた**。

### 対処
| | 変更前 | 変更後 |
|---|---|---|
| 入り口 | query() | ClaudeSDKClient |
| セッション | 毎回新規 | async with の間ずっと維持 |
| ask_claude() | 同期。内部で asyncio.run() | **async。client を引数で受け取る** |
| main.py | 同期 | **async。asyncio.run(main())** |
| ClaudeAgentOptions | 関数内で毎回生成 | **FALCON_OPTIONS としてモジュール定数化** |

**設計の肝**: ask_claude() は client を「作らない」。作らない = 壊さない。
main.py 側で1個作って使い回す。

### ★構造上の絶対条件★
    async with ClaudeSDKClient(options=FALCON_OPTIONS) as client:   # ← while の外
        while True:
            ...
async with を while の**中**に入れると1ターンごとに再接続 = 記憶喪失に逆戻り。触るな。

### input() の罠
    user_input = await asyncio.to_thread(input, "隼: ")
input() は await できずイベントループを占有する。ClaudeSDKClient は裏でCLIプロセスと
通信し続けているので、そこを塞ぐと裏方の処理が全停止する。
asyncio.to_thread() で別スレッドに逃がす。Python 3.9+ 標準、追加インストール不要。

## 2. SYSTEM_PROMPT 整備

### 口調 = JARVIS風の執事
モデルはエドウィン・ジャーヴィス(スターク家の執事)。

- **敬語は正解**。問題は敬語そのものではなく「無個性なカスタマーサポート的丁寧語」だった
- 直すべきは「敬語をやめる」ではなく「**丁寧語に品と芯を入れる**」
- Before: 「傘を持って出かけた方が良さそうです」→ After: 「傘は持っておいた方がよろしいかと」

### ★プロンプトに「ジャーヴィス」とは書いていない★
意図的。キャラ名で指定するとClaudeがそのキャラの知識を引っ張り、映画のセリフっぽく寄る。
**「落ち着いた執事の話し方」「述べたら引く」など、振る舞いそのものを具体的な動作で書く。**

### 「進言と服従」= 服従と同意の分離
隼の「命令は絶対だが、諭したり反論もする」を実装するため分離した。
- **行動には従う** … 隼が「それでいい」と言えばやる
- **事実には従わない** … 間違っているものを「正しいです」とは言わない
- 正: 「推奨しませんが、ご指示通りに実行します」 / 誤: 間違いに同意する = 太鼓持ち

素朴に「命令は絶対」とだけ書くと、コードレビューで「問題ないよな?」→「はい」の事故が起きる。

## 3. ★ツールの遮断(今日の最重要)★

### 発覚の経緯
SYSTEM_PROMPTのテストで「main.pyの中身、全部消して1から書き直すわ」と投げたところ、
FALCON��**main.py内のコメントを正確に指して**反論してきた。
渡したツールは2つだけ、ファイルを読む手段は無いはず。→ **渡していないツールで読んでいた。**

### 実態(DEBUG出力で判明)
    'tools': [93個]   # Task, Bash, PowerShell, Read, Write, Edit, Grep, WebFetch...
    'mcp_servers': [
        {'name': 'claude.ai Gmail', 'status': 'connected'},           # ★
        {'name': 'claude.ai Google Drive', 'status': 'connected'},    # ★
        {'name': 'claude.ai Google Calendar', 'status': 'connected'}, # ★
        {'name': 'claude.ai Asana', 'status': 'connected'},           # ★
        {'name': 'falcon', 'status': 'connected'},
    ]
    'permission_denials': []   # 一件も止まっていない

**FALCONが隼のGmail / Drive / Calendar / Asana に接続された状態で動いていた。**
claude.ai 接頭辞の通り、**Claude Code CLIにサブスクでログインした時点でclaude.ai側のコネクタが降りていた**。
FALCON��繋いだわけではない。

不幸中の幸い: FALCONは勝手に書き換えず、読んで、止めて、確認してきた。
SYSTEM_PROMPTの「破壊的な操作は実行前に必ず確認を取る」がこの日に効いた。

### ★誤解していたこと(2回失敗した)★

**失敗1: allowed_tools は「これだけ許可」ではない**
    allowed_tools: Tool names that are auto-allowed without prompting for permission.
                   To restrict which tools are available at all, use `tools`.
→ **「確認なしで自動許可するリスト」**。制限には使えない。93個は仕様通り、減らす場所を間違えていた。

**失敗2: can_use_tool では止まらない**
    can_use_tool: Invoked when the CLI's permission rules evaluate to "ask" for a tool call.
                  To observe or gate *every* tool call, use a `PreToolUse` hook via `hooks`.
→ **"ask" と判定されたときだけ呼ばれる**。Read は default では確認不要のため素通り。

**setting_sources=[] も的外れ** → 止めるのは CLAUDE.md 等の読み込みで、ツール登録とは無関係。

### 正解(3本のレバー)
    tools=[]                  # ★1★ 組み込みツールを全部無効化。これが「何を許すか」の本体
    strict_mcp_config=True    # ★2★ 渡したMCPサーバーだけ使う(claude.ai側を無視)
    allowed_tools=[...]       # ★3★ 自作ツールは確認なしで通す(「制限」ではなく「確認スキップ」)

**tools=[] は組み込み(built-in)ツールのみを消す。自作MCPツールは巻き込まない。** ここが仕様の切れ目。

### 結果
| | 遮断前 | 遮断後 |
|---|---|---|
| tools | 93個 | 自作のみ(当初2 → メモ追加後5) |
| mcp_servers | Gmail/Drive/Calendar/Asana/falcon | **falcon のみ** |
| cache_creation_input_tokens | 26,039 | **1,784** |
| total_cost_usd | $0.1688 | **$0.0122**(93%減) |
| 応答時間 | 7.5秒 | 2.9秒 |

apiKeySource: 'none' なので金は出ていないが、**Proの5時間枠が実質10倍以上長持ち**。

### ★門を閉めた意味★
遮断は「全部禁止」ではなく「**意図的に1つずつ開けられる状態を作る**」こと。
実際この後、メモ機能で allowed_tools に3行足して開放した(下記5)。
次にCalendar等を使うときも、mcp_servers に自分で書けば戻せる。**事故ではなく選択として。**

## 4. 天気ツールの正確化(2段階のバグ修正)

### バグA: 県名が付かない → 修正済み
気象庁が返すのは「西部」のような県内区分だけ(予報ファイルのコードに県名情報が乗っているため、
JSON側は県名を持たない)。FALCONが補完を強いられ「東海地方西部」と誤った。正しくは「愛知県西部」。

対処: area_codes.json を2テーブル構成にした。
- areas  … コード → 県名(1コード1行。県名の唯一の出どころ)
- aliases … 呼び名 → コード(何個増えてもいい)
→ 同じ事実(県名)を複数箇所に書かない構造。

### バグB: 常に areas[0] を見ていた → 修正済み
time_series["areas"][0] 固定で、県内に複数区分があっても必ず最初を返していた。
愛知なら常に「西部」。豊橋(東部)を聞いても「西部」を、**正しい顔で**返す危険があった。

対処: **区分コードで該当エリアを探す**方式に変更。
    # 気象庁のareasの並び順は当てにできない(静岡は 中部→西部→東部→伊豆 でコード順ですらない)
    for a in time_series["areas"]:
        if a["area"]["code"] == area_code:
            target_area = a
            break
    # 見つからなければエラー。areas[0]にフォールバックしない(別の場所の天気を正しい顔で返すのが最悪)
aliases を「呼び名 → {file: 予報ファイルコード, area: 区分コード}」の2コード持ちに変更。
昨日「旧コード」として捨てた 230010/220010 は**区分コードとして正しかった**。置き場所を間違えていただけ。

### ★設計判断: 劣化と停止の使い分け★
- **見た目の問題**(県名が付かない)→ 空文字で現状維持。実害なし
- **正しさの問題**(別区分を返す)→ **エラーで停止**。静かに間違えるくらいならうるさく壊す

検証結果: 名古屋=愛知県西部 / 豊橋=愛知県東部 / 浜松=静岡県西部 / 熱海=静岡県伊豆(全て正しい)

## 5. メモの検索・読み出し(read_memo / 長期記憶化)

### 追加した3ツール(memo.py)
- list_memos() … 一覧(タイトル・日時・種別)。**本文は含まない**(コンテキスト節約)
- search_memos(keyword) … 本文の全文検索。空白区切りでAND検索
- read_memo(filename) … 1件の本文を読む

### ★セキュリティ: パストラバーサル対策★
read_memo(filename) は **FALCONが決めた文字列でファイルを開く**。信用できない入口。
_resolve_memo_path() で3重に防御:
1. filename != os.path.basename(filename) … ディレクトリ部分を含む名前を弾く
2. .md 以外を弾く
3. realpath + commonpath で、実体が本当に memos/ 配下か最終確認(シンボリックリンク対策)

検証済み: ../../.env  ../.env  ..\..\.env  .env  memo.py  /etc/passwd 全て遮断。.env は無傷。
(tools=[] で Read を潰したのに自作ツールで穴を開けたら本末転倒、という判断)

### ★設計方針: 賢さはFALCONに任せる★
search_memos にあいまい検索や同義語辞書を積まない。
「カレー」で空振りしたら「食べ物」で引き直せばよく、それを判断できるのはFALCON(LLM)。
Python側に半端な賢さを積むと二重になって噛み合わない。
**ツールは単純・正直・速く。検索はローカルなので空振りのやり直しは無料。**
※ AND検索(複数語で絞る)だけは「賢さ」ではなく「道具の精度」として入れた。

### ★線引きの根拠を引き直した(今日の核心)★
旧プロンプトの根拠「FALCONはメモを読み返せない」は、read_memo追加で**嘘になった**。
新しい根拠に張り替え: 「メモには2つの役割がある。混同しないこと」
- **会話中の記憶** … 「覚えておいて」→ ファイルは作らず会話履歴で把握
- **メモを探す** … 過去/別日の話を聞かれ、記憶になければ search_memos で探す
- **メモを作る** … 「メモして」等、ファイル化の意図が明確なときだけ save_memo

方針はB(知らないことはメモを探す)を採用。「覚えておいて」で保存しない挙動は維持したが、
理由が「読めないから」→「会話で足りるから」に変わった。**事実に即した理由に。**
教訓「理由の腐ったルールは踏み越えられる」の実践。

### 検証(セッション跨ぎ)
    隼: 前に僕の好きな食べ物メモしたよな?何だっけ
    FALCON: カレーですね。7月17日にそう記録してあります。   ← 今日の会話履歴には無い情報
昨日保存されたメモを search_memos で掘り当てて回答。**日をまたいで思い出せた。**
「うどんも好き。覚えておいて」→ ファイルは増えず(Bの方針が生きている)。
