## 1. PCのRGB消灯(寄り道)

「使わない時は画面を真っ黒にしたい」の話から派生し、PCケースファンの常時点灯が気になるという話に。

### 経緯

1. マザーボード(ASUS PRIME H610M-A D4)の`Aura Sync`を確認 → 「デバイスを同期」タブに登録されてるのは`PRIME H610M-A D4`本体と`Addressable LED Strip`のみで、ケースファンは対象外と判明
2. `OpenRGB`を導入して試すも、`Aura Addressable 1/2/3`のどのゾーンを操作してもケースファンは無反応 → マザーボード直結ではないと確定
3. ケースの型番(MSI MPG GUNGNIR 110R WHITE)を特定 → 一般論として、この手のケースは前面パネルに物理LEDボタンを持つことが多いと判断
4. **前面パネルのボタン長押しで消灯に成功**

### 教訓

RGBデバイスは全部がソフト制御下にあるわけじゃない。ケース付属の独立ハブは、マザーボードのソフト(Aura Sync)からもサードパーティツール(OpenRGB)からも見えないことがある。ソフトで詰まったら、まず物理ボタンを探す方が早いことがある。

## 2. PCの電源設定の整備

### 省電力化(Windows側の設定変更)

「使わない時にPCのディスプレイを真っ黒にしたい」「できる限り省電力にしたい」の要望に対応。

- 電源プランを「省電力」に切替(`powercfg /setactive a1841308-3541-4fab-bc81-f71556f20b4a`)
- **スリープは無効化のまま維持**(`standby-timeout-ac = 0`) … FALCONサーバー・Tailscaleの到達性を保つため、0721で決めた方針を継続
- ディスプレイ消灯を3分に設定(`monitor-timeout-ac = 180`)
- ネットワークアダプタ(Intel Ethernet I219-V)の「電源の管理」は、確認の結果既にオフ設定になっており対応不要だった
- 「高パフォーマンス」プランもスリープ無効(AC側)がデフォルトになってることを確認済み。両プランとも安全に切替可能

### ★新機能★ FALCONから電源プランを操作できるようにした

隼の「FALCONに『省電力にして』と言えば切り替わるようにしたい」という要望を受け、新しいツールを追加。

**新規ファイル `core/tools/power.py`**
- `set_power_plan(mode)` … `powercfg /setactive`のラッパー。`mode`は`power_saver`/`balanced`/`high_performance`
- `get_power_plan()` … 現在アクティブなプランを取得
- GUIDを直書きせず、Windows標準のエイリアス(`SCHEME_MAX`=省電力等)を使うことで環境差に強くした

**発生したバグと対処**

`get_power_plan`が`UnicodeDecodeError: 'cp932' codec can't decode byte 0x81`で失敗。`subprocess.run(text=True)`がPythonのデフォルト文字コード(cp932)で`powercfg`の出力を自動デコードしようとして失敗していた。`capture_output=True`のみにして生バイトで受け取り、UTF-8→cp932の順に試すデコード関数(`_decode`)を自作して解決。`set_power_plan`側は元々`text=True`を使っていなかったため無傷だった。

**`brain.py`への統合**
- `set_power_plan_tool` / `get_power_plan_tool`を追加、`allowed_tools`にも登録
- SYSTEM_PROMPTに「電源プランの切替は可逆的で実害が無いため、確認なしで即実行してよい」というルールを追加(`delete_task`等の破壊的操作とは扱いを分けた)
- `SCENARIOS`に`power`シナリオを追加(実データを汚さないため後片付け処理は無し)

### 検証

`python core\brain.py power`で「今の電源プラン教えて」→「省電力にして」→「普段通りに戻して」の3ターンが想定通り動作することを確認済み。

## 3. `core/tools/calendar.py`の名前衝突を解消

### 再現条件(0722_01で特定済みの原因を最終確認)

`weather.py`が使う`requests`(内部の`urllib3`/`email.utils`経由)は標準ライブラリの`calendar`モジュールを`import`する。`python core\tools\weather.py`のようにスクリプトを直接指定して実行すると、Pythonがそのスクリプトのディレクトリ(`core/tools`)を`sys.path`の先頭に挿入するため、`import calendar`が標準ライブラリではなく自作の`core/tools/calendar.py`を先に掴んでしまい、`ModuleNotFoundError`で落ちる。

### 対処

`git mv core/tools/calendar.py core/tools/gcal.py`でリネーム。`brain.py`のimportも`from core.tools.gcal import list_events, create_event`に修正。リポジトリ内で`core.tools.calendar`を参照してたのは`brain.py`の1箇所のみだった。

### 検証

`python core\tools\weather.py`(名古屋・豊橋・浜松・熱海・豊田の5地点)、`python core\brain.py calendar`ともにエラー無く動作することを確認済み。

## 4. PWAアイコン(仮実装)

### デザイン

ミニマルな「M字型」1本のストロークで、飛翔する鳥のシルエットを表現。理由は、favicon(32px)クラスの極小サイズでも潰れず視認できることを優先したため。色はUIの配色(背景`#1a1a1a`+アクセント`#2b5278`)から流用……だったが、**この後UIを全面刷新してオレンジ系(`#ff8a3d`)に変わったため、現状アイコンの色とUIの配色は合っていない**。隼が本番の画像を用意するまでの仮アイコンという位置付けなので、今は許容。

### 実装

`static/icons/`ディレクトリを新設し、4サイズを配置。
- `icon-192.png` / `icon-512.png` … Android/Chrome系(`manifest.json`の`icons`から参照)
- `apple-touch-icon.png`(180px) … iOS Safariの「ホーム画面に追加」用。**manifest.jsonのiconsはiOSでは見られないため、`<link rel="apple-touch-icon">`が別途必須**
- `favicon-32.png` … ブラウザタブ用

### 本番画像への差し替え方法

隼が画像を完成させたら、同じ1枚の画像から上記4サイズを書き出し、**同じファイル名で`static/icons/`を上書きするだけ**でよい。コード側の変更は不要。

## 5. ★UIの全面刷新(JARVIS風ダークテーマ)★

隼が用意したデザインモックアップ(オレンジ系アクセント、モノスペースフォント、ターミナル調チャットログ、CPU/MEM/NET使用率バー、処理中インジケーター)を元に、`static/index.html`を全面的に作り直した。

### 決定した方針

- **背景の「脳のワイヤーフレーム画像」は今回省略** … `#brain-visual`という空のdivだけ用意。将来、隼が画像を用意したら`background-image`を1行足すだけで差し込める構造にしてある
- **CPU/MEM/NETバーは将来的に実データと連動させたい、との要望** → 今回のスコープ内で実装(下記)

### 新規実装: `/system-stats`エンドポイント

**新規ファイル `core/tools/system_stats.py`**
- CPU: `psutil.cpu_percent(interval=None)`。`interval`を指定すると呼び出しがブロックするため、意図的に`None`にして「前回呼び出しからの変化率」を返す方式にした(2秒おきにポーリングされる前提と相性が良い)
- MEM: `psutil.virtual_memory().percent`をそのまま使用
- NET: 正確な「回線使用率」を出す方法が無いため、**送受信バイト数の増加量÷経過時間で算出したスループットを、暫定基準値(2MB/秒)に対する割合として近似表示**する設計にした。実測値ではなく見た目のための目安である旨をコード内にコメントで明記

`server.py`に`GET /system-stats`を追加し、`system_stats.py`を呼ぶだけの薄いエンドポイントにした。`requirements.txt`に`psutil`を追加。

### `static/index.html`の全面書き換え

既存の実機能(`/chat`への送信、`/history`の読み込み)のロジックはそのまま維持し、見た目とマークアップだけ刷新。

- ヘッダー: ロゴ「FALCON」+ サブタイトル「AI CORE INTERFACE」、CPU/MEM/NETバー、「待機中/IDLE」⇔「処理中/PROCESSING」の状態インジケーター(送信中はパルスアニメーション)
- チャットログ: `>`(隼、アクセント色)/ `FALCON>`(FALCON、控えめな色)のターミナル風表示。プロンプト文字列は**CSSの`::before`ではなくJSで直接テキストとして設定**(コピー・アクセシビリティを考慮)
- 入力欄: `❯`のプロンプトアイコン + 丸い送信ボタン
- **モバイル幅(600px以下)ではCPU/MEM/NETバーとサブタイトルを`display:none`で非表示** … モックアップのモバイル版もバー無しのシンプルな構成だったため、それに合わせた
- `100dvh`(0721で対処したモバイルSafariのアドレスバー問題)は維持。`viewport-fit=cover`と`env(safe-area-inset-bottom)`を追加し、iPhoneのホームバーと入力欄が重ならないようにした

### 検証

PC・モバイル両方でスクリーンショットを確認。ヘッダー・バー・チャットログ・入力欄すべて想定通り表示され、「隼様とお呼び」のような呼称変更の会話も問題なく動作。モバイル側は初回リロード直後でチャットログが空に見えたが、実際にメッセージを送ってみて問題無く動作することを確認済み(バグではなく単に履歴が無い状態だっただけ)。

## メモ

- `psutil.cpu_percent(interval=None)`は「前回呼び出しからの変化率」を返す仕様のため、ポーリング前提の設計と相性が良い。単発で正確な瞬間値が欲しい場面では`interval`を指定する必要がある点は注意
- `powercfg`の出力デコードで踏んだ`cp932`の罠は、Windows環境でsubprocessの出力を扱う時に再発しうる典型パターン。`text=True`を安易に使わず、生バイトで受けて自前でデコードを試す方が安全な場面がある、という教訓
- RGBデバイスやケース付属ハブなど、「ソフトウェアから見えないハードウェア」の存在は、トラブルシューティングの初手を見誤らせやすい。ソフト側を疑う前に、まず物理的なボタン・スイッチの有無を確認する方が早いことがある
