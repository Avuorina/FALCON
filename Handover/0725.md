## 1. Minecraftサーバー管理、設計の紆余曲折

今日は方針が何度か変わった。時系列で残しておく(次回、同じ迷い方をしないため)。

### 第1案: RCON前提、1サーバー固定
`start_server`/`stop_server`/`get_status`をRCON経由で実装。`mcrcon`ライブラリの実物をinspectで確認し、
実機で`start`/`status`/`stop`を検証 → 全て成功。しかしここで隼から「サーバーは37個ある(バニラ21+Modpack16)」
と判明し、1台固定の設計が破綻。

### 第2案: 「スキャン+登録制」に変更
`config/minecraft.json`に`scan_dirs`(物理フォルダをその場でスキャン)と`servers`(操作可能な登録済みのみ)を
分けて持つ設計に変更。ここで隼から既存プロジェクト`MCserverManager`(C#/WPF)の存在が明かされる。

### 第3案: MCServerManagerの`servers.json`を直接読む方式 → 不採用
`%APPDATA%\MCServerManager\servers.json`を読めば二重登録が要らないと考えたが、
「このアプリは利用せず、FALCONに流用したい」という要望で不採用。ただし中身の調査で2つの収穫があった:

- **ポート自動検出のロジック**(`server.properties`の`server-port=`を正規表現で読む) … FALCON側にも移植
- **`MineStat`(C#)の存在** … RCON不要でServer List Ping(マイクラのマルチプレイ画面と同じ仕組み)により
  プレイヤー数が取れると判明。Python版の`mcstatus`ライブラリで同じことができると確認(`JavaServer.lookup(host:port).status()`)

### 第4案(現状): RCON不要のstatus + RCON限定stopのハイブリッド設計 → 完成、ただし`brain.py`未登録
- `list_minecraft_servers` / `start_minecraft_server` / `get_minecraft_status`(mcstatus、RCON不要) /
  `stop_minecraft_server`(RCON必須、`config/minecraft_rcon.json`に登録したサーバーのみ対応)
- `core/tools/minecraft.py`としてコード設計は完了しているが、**`brain.py`への`@tool`登録はまだ行っていない**
  (下記「ダッシュボード」の話に発展したため中断)

### 方向転換: 「会話でstart/stop」より先に「ログを見たい」
隼から「色々やる場合のサブ画面としてアプリを作りたい。マイクラサーバのログを画面に表示させたり」という
要望が出て、Minecraftの`brain.py`登録は一旦保留。**ログ表示専用の最小構成**で`config/minecraft.json`を作り直した:

```json
{
  "servers": {
    "vanilla": { "server_dir": "E:\\Minecraft\\server\\server\\バニラサーバー\\26.1.2" },
    "AllTheMons": { "server_dir": "E:\\Minecraft\\server\\Modpackserver\\ATmons" }
  }
}
```

`core/tools/minecraft.py`もログ取得(`list_servers` / `get_log_tail`)のみのシンプルな内容に絞って実装した。

## 2. `server.py`へのエンドポイント追加(ログ表示用)

```python
@app.get("/minecraft/servers")
async def minecraft_servers():
    return minecraft.list_servers()

@app.get("/minecraft/{server}/log")
async def minecraft_log(server: str, lines: int = 100):
    return minecraft.get_log_tail(server, lines)
```

`get_log_tail`はログファイル全文を読まず、末尾N行だけを返す設計にした(ログは肥大化し続けるため)。
ブラウザから直接叩いて動作確認済み(`/minecraft/servers` → `{"servers":["AllTheMons","vanilla"]}`、
`/minecraft/vanilla/log?lines=20` → 直近の起動・入室・停止ログを正しく取得)。

## 3. ★新規プロジェクト: FALCON-Dashboard★

### 位置づけ
FALCON本体(PWA、iPhone・ブラウザ向け)とは別に、**デスクトップ向けのサブ画面アプリ**として新規作成。
Minecraftログに限らず、今後増える「会話だけでは扱いにくい情報」を表示する窓口にする想定。

### 技術構成
- C# / WPF、.NET 8.0(`MCServerManager`とバージョンを揃えた)
- MVVMパターン。`Services/FalconApiClient.cs`にFALCON本体との通信を集約
- タブ構成: 「チャット」「Minecraftログ」の2枚。各タブは`UserControl` + 専用`ViewModel`

### 通信方式
- FALCON本体(`server.py`)に、Tailscale経由のHTTPS(`https://desktop-0cl2p6m.taila09f6b.ts.net:8000`)で接続
- チャット: `/history`(履歴取得)・`/chat`(送信)を叩く。**PWA版と会話履歴を共有**
- Minecraftログ: `/minecraft/servers`・`/minecraft/{server}/log`を**3秒おきポーリング**で取得(WebSocket等のリアルタイム配信は今回不採用、実装のシンプルさを優先)

### GitHubリポジトリ
`https://github.com/Avuorina/FALCON-Dashboard`(Public、MIT License)

途中でフォルダ名のタイプミス(`FALCONDashbord`→`FALCONDashboard`への訂正)が絡み、
以下の2つのトラブルが発生・解決済み:

1. **ビルド成果物(`bin`/`obj`/`.vs`/`*.csproj.user`)を`.gitignore`作成前に誤ってコミット**
   → `git rm -r --cached`で追跡解除(ディスク上のファイルは残したまま)、`.gitignore`追加後に再コミットして解決
2. **`.slnx`ファイルが古いフォルダ名(`FALCONDashbord/FALCONDashboard.csproj`)を指したままでビルド不可**
   → `.slnx`内のパスを`FALCONDashboard/FALCONDashboard.csproj`に手動修正して解決

### 動作確認
- 「チャット」タブ: 「隼: こんばんわ」→「FALCON: こんばんは、隼。何かお手伝いすることはありますか。」で正常動作、サーバー版と会話履歴共有も確認
- 「Minecraftログ」タブ: `vanilla`選択でRCON起動シーケンス・プレイヤー入室ログまで正しく表示、Tailscale経由でノートPCから実機確認済み
